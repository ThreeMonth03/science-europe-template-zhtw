# 0.3.41：Q15 固定敘述合段

這輪把前次 A/B 診斷接回英文共用 Jinja，再循既有工具產生中文。
沒有另外維護中文 Jinja，也沒有用 LLM 改寫填答。748 組翻譯原封保留。

只有「不需要額外軟硬體」且已明確回答儲存庫是否收費時，兩句固定敘述才合成一段。
英文句間保留一個空格，中文句號後直接接下一句；不修改句號字形或標點內容。
兩項事實的識別仍存在；收費狀態 `complete` 指已回答，不代表免費。
自由回答、缺答、未知選項、複雜標記及過長譯句都不套用合段。

同一套來源供 HTML／PDF／Word、內部檢核／提交預覽使用。沒有擴大「可關閉提示」
的範圍，提交預覽仍不是任意專案都可直接繳交的正式版本。
PDF 短區塊規則只加認這一個明確的行內事實；原本長度、表格、筆數限制不放寬。
不改 CSS、字型、Word filter 或 reference.docx。

## 版本與驗證

仍用既有工作分支、英文來源 commit 與中文 `pipeline.yml` 精確鎖定；
檢核版／提交版是同一版本的輸出選項，不各開長期分支。
新增逐項逆向比對，先還原 0.3.40 的全部來源與中英 prepared-source hashes，
再跑既有歷史檢查，不能靠重設基準放過未審閱變更。
未來 upstream 改到這段時，需在升級分支審閱目的與重跑對照，不直接整檔覆蓋。

500 組中英分支檢查涵蓋未填、空值、未知、是／否、失效子答、自由文字／連結及
兩種 escaping 設定；40 組觸發合段，其他輸出逐字相同。原生 DSW 成品另行核對，
不能以離線 PDF 或單元測試代替。Microsoft Word 實機與代表性真實專案仍待驗收。
