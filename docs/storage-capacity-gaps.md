# Q3 儲存容量漏填：0.3.32 實驗

問題不是 PDF parsing：前版選擇「我可以說明總資料量」卻未填數量時，
Q3 只留下「資料儲存與檔案規則」標題；有其他回答也不會出現待補提示。
只填空白更會產生「儲存空間為 GB」這種不完整句子。

這輪在有效追問分支、數量缺答或全空白時顯示：

> 尚待補充：計畫所有資料與軟體（含暫存空間）所需的預估儲存容量（GB）。

已填答案改為「預估計畫所有資料與軟體（含暫存空間）所需的儲存容量為
{size} GB。」英文補上 `to be`。數值不轉型、不推算；0 保留，輸入中
類似 HTML 的字串只當文字呈現。自填命名規則等段落不改寫。
未選探索、未選指定容量、未知選項和「容量很少」不套用這項缺值提示，
也不虛構肯定或否定答案。其他 Q3 缺答仍須另外檢查。

只改英文 Q3，中文仍由既有展開／翻譯流程生成。735 組翻譯中，原 734
組保留 733 組；改 1 組容量敘述、增 1 組提示。Q3 以外翻譯檔逐位元
相同。共用 CSS、Word Lua、字型與 reference 不動，提示重用 reading-gap
容器，避免被合併進固定政策句。中英全 Q3 DOM 共 1,732 組檢查；歷史
Q2 的 528 組、Q11 的 548 組分支與 128 組缺答組合仍執行，不放寬舊證明。

兩 repo 由 0.3.31 開 `fix/q3-storage-gaps`；中文精確鎖定英文 commit。
這是工作分支，不是每個 patch 另養一條永久維護線。未來上游改到 Q3，
須重驗 KM UUID、追問可達性、GB 單位、翻譯差異及原生格式，不以 Git
無衝突代替成品驗收。官方基底仍是 1.30.1，本輪不升級也不部署正式站台。

六組雙語原生測試規劃：缺容量但有後設資料、全空白容量且有其他回答、
0、2048、整份空白、明確否定。PDF／可編輯 DOCX／LibreOffice 預覽
必須另有實際產檔證據；它們不等於 Microsoft Word 或全篇 DMP 驗收。
