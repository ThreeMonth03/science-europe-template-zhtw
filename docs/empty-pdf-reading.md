有明確條件的規則；中文更新來源 lock，731 個翻譯檔與生成用 Jinja 不變。
不另建永久中文排版分支，也不修改 Word Lua／reference、字型或引擎。

空白 Q15 原本四項缺答各有一個框，重複內距與段距使中文整組掉到第四頁。
現在只有「專業知識、硬體軟體、儲存庫費用、經費與時間」依序四項、全部
標為 missing、且沒有額外回答元素時，才共用一個框。四項仍是獨立段落，
完整標籤、文字、順序、屬性都保留，沒有縮字、隱藏文字或合併作者回答。

補產短預算部分漏答、長預算漏幣別的基準，才與新版進行同資料比較。

只有空白中文頁數可少一頁，其他 PDF 正文分頁與全部 Word 本文 XML／樣式／
連結／預覽頁數應不變。短預算提示折行尚未修正，不能將控制組不變稱為已改善。

## 升級與 CI

來源範圍檢查改以保存的 0.3.23 為基準：除了 `layout.css`，其餘 prepared src
都須完全相同；移除新增 panel 區段後，CSS 也必須與前版逐位元相同。
731 個翻譯檔逐一核對，不以「翻譯檔數一樣」代替內容比較。
舊 Q8／Q9 的「只能改 Lua」範圍檢查留給各自歷史版本，不放寬原報告；
CI 仍執行 Q8／Q9 的 AST 與實際 DOCX 探針，並加入英中 panel 引擎探針。

官方基底仍為 1.30.1，來源 commit／候選 ZIP／樣張 hash 分開記錄。
Git 無衝突不代表版面相容；未來改 Q15 結構或上游 CSS，必須重跑原生樣張。
尚未完成 Microsoft Word 實機、整篇語氣及 stock worker Markdown 表格驗收；
沒有操作線上 DSW、keyring，沒有合併 main、建立 tag 或發布。

## 探針與初版 CI 失敗

初版中文片段探針與 CI 都以 exit 139 失敗，未將它當成通過。檢查發現 prepared
CSS 的字型仍含 `assets(...)` Jinja placeholder，測試程式未像原生 DSW 展開。
補入同一份字型後，即使不加入文件保留修正，對照實驗也可通過；正式探針同時
保留文件／字型設定到版面檢查完成，並在失敗時保存 stderr 與 return code。
不是換引擎或跳過中文。兩個修正僅涉及測試程式，實際成品 ZIP 必須與原生測試
使用的初版候選逐位元相同；來源 commit 不同會如實記錄於各自 manifest。
