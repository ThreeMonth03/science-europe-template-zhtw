# Word 全空節：局部縮距與連頁原型

這輪針對稀疏填答時中文提交 Word 的第 15 題獨占尾頁。正式中英來源仍為
0.3.49，未接回正式來源、升版、推送或部署。原型採獨立模板 ID；中文仍由
既有鎖定轉換工具產生，不維護另一套中文條件邏輯。

## 為何不只縮小間距

第一版將全空節 Heading2 改為段前 6pt／段後 3pt；中英範圍檢查、建置及
28 組文件都能產生，但實際中文漏填案例仍有第 15 題孤頁，因此判定失敗。
後續私下掃描 4pt／2pt、3pt／2pt、2pt／2pt 發現：單純再縮距會讓另一個
原本末頁有多題的案例變成只剩第 15 題，不能只看總頁數沒有增加就放行。

第二版使用 3pt／2pt，並將同一全空節的非末題與下一題保持連頁。
仍保留節標題的既有 keep-next、全部題目、字級、outline 與最後一題的可分頁性；
有答案或未知結構的節完全不處理。最多四題的空節作為完整閱讀單位，
不把研究者的長回答綁成不能分頁的大區塊。

## 範圍與可追溯性

- 只改英文 `src/word/question-spacing.lua` 和 `src/word/question-spacing.xml` 兩個素材。
- `pipeline.yml`、正式翻譯樹、PDF／HTML 來源、字型、Word reference、六種格式 UUID 與轉換步驟不變。
- 775 組譯句及翻譯 Markdown 檔案逐位元不變。
- 英文實驗提交：`2f63e964c481d08b949ec4663209f3d2e0f1b8e4`。
- 中文實驗輸入：`1e0bcf3ebaa93262a1feb263c976e95bfc927fb7`。
- 正式英文基線仍鎖 `ff6eea886d27f5bca4682cd3f3c59e1701a83f10`，工具仍鎖 `25e339fbdfb1d20796471055790aad6a4226b6ed`。
- 使用短期 `fix/word-empty-section-spacing`，不建立中英或檢核／提交的永久邏輯分支。

Pandoc 的 `<section>` 會帶入額外的 `section` class；既有 Word filter 也會在
正文根節點前插入特定換頁 RawBlock。兩次初始範圍檢查已攔下判定落空，
修補後只接受這個已知序列，不任意跳過節點。最終中英各 121 個範圍案例
驗證標記與 DOCX 完整 XML 的允許差異，涵蓋額外屬性、未知 ID、錯序、
有答案、作者內容與毀損標記；不以 AST 通過取代實際文件驗收。

## 原生與視覺驗證

第二版已通過英文 262 項測試與 TDK 驗證、中文 469 項測試、中英實際套件各
121 個範圍案例及九項比較器變異測試。兩次乾淨建置逐位元一致：

- English ZIP：`720113d1bc6d7e6e65ae17108727ac21e0e300fb7e59d8589fbfde830a3004d8`。
- 中文 ZIP：`3e7cf77e37d1700b7a011f482fa8a22998c5c8b81f3a7ae62608c918d91c6c86`。

28 組原生對照全部通過：130 頁 PDF 的文字位置、字型及逐頁影像完全不變；
Word 預覽共 133 → 131 頁，沒有任何案例增頁。14 組檢核版與四組真實快照
提交版的 Word 組件（除建立／修改時間）、位置與逐頁影像均不變，共 108 頁。
其餘十組提交 Word 只允許已識別的節標題間距與空題 keep-next 變更，其他
XML、字型、連結、書籤及使用者文字必須一致，且每個受影響的全空節須保持同頁。

| 提交案例 | English Word | 中文 Word | 結果 |
| --- | --- | --- | --- |
| 全空 | 2 → 2 | 2 → 2 | 全部十五題保留 |
| 漏填子題 | 2 → 2 | 3 → 2 | 第十五題孤頁消失 |
| 明確否定 | 2 → 2 | 3 → 2 | 否定原文保留，孤頁消失 |
| 肯定 | 2 → 2 | 3 → 3 | 最後一節完整換頁，不再拆成孤題 |
| 長標準名稱 | 3 → 3 | 3 → 3 | 長文保留，空節不拆頁 |

人工抽看最終中英九頁。中文肯定案例最後一頁仍偏空，這是保留完整節的
取捨，不宣稱所有頁面密度已最佳化；詳見 `native/visual-review.json`。
正式整合前的下一步是將兩個素材及守門檢查接回共用來源，配對升版後重跑
完整候選 workflow 與原生一致性檢查，不直接將實驗 ID 當正式版本發布。
