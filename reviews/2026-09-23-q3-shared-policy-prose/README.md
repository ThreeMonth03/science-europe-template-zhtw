## 修改範圍

英文 recipe 只在 Q3 擷取 metadata-policy 片段並加一份共用 helper。
整段必須恰為 2–3 個純文字固定段落，而且**每個邊界都是中文句號接 BMP 漢字**，
才合併並省去模板原先插入的 ASCII 空格。字典事實屬性保留在 span；
文字、肯定／否定狀態、順序與原有內部空格不變。PDF 和 Word 共用同一個決定。

只要有英文／混合邊界、使用者原文、缺漏提示、複雜標記、實體字元、未知屬性、
重複字典事實或不完整句子，**整段逐位元原樣回退**，不做局部合併。
CSS、Lua、Word 樣式、字型、轉檔步驟，以及 775 份翻譯檔全部不變。

初版曾合併英文並保留空格，但實際 PDF 控制案例出現 **0.013055 pt** 座標差，
且 72 dpi 像素改變，因此被否決。失敗產物和程式另行封存，沒有放寬容差來通關。
新版未接句案例要求 HTML bytes、DOCX 組件（建立／修改時間戳除外）、
PDF／Word 預覽的文字座標與逐頁像素完全相同。

## 限制與下一步

本輪不是全文件排版修復：中文語氣、全形 `）。` 的字寬、Word 既有行距均未改。
同一 Q3 控制提交文件，PDF 原本與現在都是 2 頁，Word 預覽都是 3 頁；
不能把這種跨格式差異說成已解決。LibreOffice 不等同 Microsoft Word 驗收；
本機測試不等同 GitHub Actions。本輪未重跑正式 54 項整合 workflow，
未呼叫 DSW API。

下一步才把最小來源差異整合到英文，保留舊證據並更新版本化投影測試，
中文鎖定新的完整英文 commit、配對升版，再跑正式整合驗證。
升級時先以鎖定來源檢查差異；未審查的來源漂移讓建置失敗，
未知段落形狀則在執行時原樣回退，不強行合併。
之後另做 Word 行距與整頁閱讀節奏實驗，避免把不同問題混成一次大型修改。
